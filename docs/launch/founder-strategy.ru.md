Не «человек, который обещает цифровую сингулярность», а:

> **Artem (`@artemiosu`) — создатель evidence-first подхода к эволюции агентов: claims становятся lineage, tests и rollback, либо не наследуются.**

Это согласуется с уже начатым направлением `business-skills`: evidence-first agent skills можно связать с evidence-first agent evolution.

## Контентные опоры

### 1. Build logs

Раз в неделю:

- что пытались доказать;
- какой кандидат провалился;
- что показали данные;
- какая архитектурная гипотеза изменилась;
- следующий falsifiable test.

### 2. Variaxiom Trials

Каждый Trial подписан автором и внешними соавторами/reproducers. Это формирует searchable body of work, а не поток мнений.

### 3. Архитектурные эссе

Темы первых материалов:

1. Self-editing is not self-improvement.
2. Why agent memory needs a germline.
3. Capability is not authority.
4. Why a swarm can be a tumor.
5. The evaluator is the real product.
6. How to measure an improver, not only an agent.

### 4. Public corrections

Создать `CORRECTIONS.md` или section в release notes. Быстрая открытая коррекция повышает доверие сильнее, чем попытка выглядеть всегда правым.

## Как писать ключевым людям

Не просить «посмотрите мой гениальный проект» и не отправлять длинный манифест.

Формат:

```text
Subject: Can you break this proof gate for self-modifying agents?

I built a minimal open-source experiment inspired by [specific work].
It rejects an agent change that passes functional tests because the
candidate silently expands authority.

One command / 90 seconds: [link]
Architecture claim: [one sentence]
What I may be wrong about: [specific point]

I am not asking for endorsement. A counterexample or relevant prior art
would be more valuable, and I will credit it publicly.
```

## Relationship ladder

1. Изучить конкретную работу человека.
2. Воспроизвести/применить её с credit.
3. Задать один точный вопрос.
4. Реализовать полученную критику.
5. Публично показать изменение и credit.
6. Предложить совместный Trial/RFC.
7. Только затем обсуждать advisory, sponsorship или инвестиции.

## Что не делать

- массово отмечать известных людей в launch thread;
- притворяться, что они «в экспертном совете»;
- использовать их имена как social proof без согласия;
- спорить с критикой ради сохранения образа;
- публиковать слишком много абстрактной философии без кода;
- обещать сроки/результаты, которые нельзя проверить;
- закрывать проект для вкладов ради сохранения полного авторского контроля.
