# M2.1 disabled verifier implementation plan

- **Tracking issue:** [#11](https://github.com/artemiosu/variaxiom/issues/11)
- **Normative specification:**
  [`../specs/m2.1-identity-grants-signatures.md`](../specs/m2.1-identity-grants-signatures.md)
- **Frozen corpus:** `fixtures/conformance/v2/` — 237 cases, inventory SHA-256
  `2cf14b99c2f22cbe1b56588d9ae8901fc79ab22f57328bf6c9dd8432101212d4`
- **State:** implementation in progress; stages one and two complete; disabled and non-authorizing

## Implemented slices

- Python and Rust own the untrusted bytes before decoding;
- the 1,048,576-byte bound is applied before parsing;
- strict UTF-8, duplicate-member, depth, number-profile, and canonical-byte checks return the
  frozen stage-one codes;
- accepted bytes and their SHA-256 digest are retained in immutable snapshots;
- all eight frozen stage-one failures and the exact-size success case run through both APIs;
- no decoded caller-owned mutable object crosses into later verification stages;
- explicit verify, historical replay, initialize, and advance entry points exist in both runtimes;
- exact object shapes, nested versions and kinds, protocol-token rules, collection ordering and
  uniqueness, and normative resource bounds are checked before any trust or crypto work;
- all 78 frozen stage-two rejections return the exact frozen code in Python and Rust;
- all 151 cases assigned to later stages pass the stage-two boundary in both runtimes;
- an externally supplied trusted anchor is canonicalized into an owned snapshot before later use.

## Fixed boundary

This change may implement parsing and verification only. It must not modify the accepted M2.1
specification, schemas, fixture inputs, expected outcomes, or inventory. Any discovered contract
defect stops implementation and returns to a separate specification change.

The implementation has no signing or private-key API, no ambient clock/network/filesystem trust,
no promotion-gate wiring, and no lineage append. A successful verification result is data only and
cannot authorize a side effect.

## Delivery slices

1. **Complete:** add explicit non-authorizing verify, historical replay, initialize, and advance
   entry points with owned input snapshots.
2. **Complete:** add structural stage-two validation without importing fixture generator/oracle
   code into production modules.
3. **Next:** implement digest, actor/key/domain/role, trust-anchor, and policy stages in normative
   order.
4. Add strict Ed25519 verification using locked minimal dependencies and no signing features.
5. Run every frozen case through the production Python API and the Rust API; compare all result
   fields and exact returned anchors with the independent fixture oracle.
6. Add direct API mutation, no-ambient-authority, and resource-exhaustion tests.
7. Reproduce from a clean clone on the supported operating-system matrix and repeat the three-role
   automated review before marking the implementation ready.

## Review checkpoints

- parser/result types before policy logic;
- trust-anchor transitions before signature verification;
- strict cryptographic profile before full proposal verification;
- complete differential corpus before any merge;
- a later, separate decision before connecting the verifier to promotion or durable lineage.

## Rollback

The implementation remains unreachable from the active v1 promotion path. Reverting its modules,
tests, and dependency additions restores the accepted schema/fixture baseline without migrating
state or changing existing canonical identities.
