## Fixed boundary

This change may implement parsing and verification only. It must not modify the accepted M2.1
specification, schemas, fixture inputs, expected outcomes, or inventory. Any discovered contract
defect stops implementation and returns to a separate specification change.

The implementation has no signing or private-key API, no ambient clock/network/filesystem trust,
no connection to the active promotion path, and no lineage append. A successful verification
result is data only and cannot authorize a side effect.

5. **Complete:** add strict Ed25519 verification using locked minimal dependencies and no signing

6. **Complete:** implement evidence subject binding, grant semantics, pinned constitution/artifact

7. **Complete:** implement stage eleven decision recomputation and selector verification, retaining
   replay/history non-authorizing semantics.
8. **Complete:** run every frozen case through the production Python API and the Rust API; compare all result
   fields and exact returned anchors with the independent fixture oracle.
9. **Complete:** retain direct API mutation, no-ambient-authority, and resource-exhaustion tests
   across the staged boundaries and terminal result.
10. **Next:** reproduce from a clean clone on the supported operating-system matrix and repeat the three-role
   automated review before marking the implementation ready.

## Review checkpoints

- parser/result types before policy logic;
- trust-anchor transitions before signature verification;
- strict cryptographic profile before full proposal verification;
- complete differential corpus before any merge;
- a later, separate decision before connecting the verifier to promotion or durable lineage.

## Rollback

The implementation remains unreachable from the active v1 promotion path. Reverting its modules,
tests, and dependency additions restores the accepted schema/fixture baseline without migrating
state or changing existing canonical identities.
