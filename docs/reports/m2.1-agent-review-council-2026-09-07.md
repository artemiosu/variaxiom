# M2.1 independent automated security-council report

**Date:** 2026-09-07  
**Initial reviewed commit:** `d7a282947112a76d8e003155f0d0d3e03f6a5235`  
**Target:** PR #4, M2.1 specification and ADR 0010  
**Reviewer type:** three isolated automated agents; no human or organizational independence claimed  
**Initial verdict:** unanimous REQUEST CHANGES

## Independent mandates

- cryptographic protocol: Ed25519 acceptance, signing domain, key identity, replay and revocation;
- authority threat model: trust roots, grant scope, role separation, confused deputy, stale lineage;
- implementability/conformance: exact wire shapes, stable failures, bounds, fixtures and Python/Rust
  determinism.

Reviewers were read-only and submitted findings independently. GitHub Copilot review was requested
as an optional fourth signal, but GitHub did not assign the reviewer; it is not counted.

## Blocking findings and remediation

| ID | Initial severity | Finding | Normative remediation |
|---|---:|---|---|
| C-01 | P0 | Embedded identity context could mint its own trust | Separate pinned authorization anchor; exact domain/digest/sequence/time check before lookup |
| C-02 | P0 | M1 evidence could replay across adjacent candidates | `evidence/v2.subject_candidate_digest` binds the full candidate envelope |
| C-03 | P1 | One key could represent multiple principals | Globally unique key→principal binding; v1 reassignment forbidden |
| C-04 | P1 | Proposer could issue/select its own change | Normative proposer/verifier/issuer/selector separation matrix |
| C-05 | P1 | Grants portable across deployments/policies | Bind trust domain, capability vocabulary, constitution and lineage |
| C-06 | P1 | Old snapshot/time could authorize new work | Separate `authorize_new` and non-authorizing historical replay APIs |
| C-07 | P1 | Selector signature did not bind durable transition | M2.1 narrowed to attested proposals; exact-head CAS deferred to M2.2 |
| C-08 | P1 | Ed25519 library acceptance could diverge | Rust `verify_strict`, equivalent Python prechecks, normative invalid corpus |
| C-09 | P1 | Wire objects and failure precedence incomplete | Exact shapes, schemas, first-error stages and verification-result contract |
| C-10 | P1 | No bounded resource profile | Fixed byte/member/depth/crypto-operation limits and boundary vectors |
| C-11 | P2 | Signing-message line feeds ambiguous | Explicit ASCII concatenation with `0x0A` and golden message bytes |
| C-12 | P2 | Capability strings had unstable semantics | ASCII grammar plus versioned capability namespace; no wildcard/normalization aliases |
| C-13 | P2 | Key compromise response unspecified | Emergency freeze, revoke, rotate, repin and non-authorizing replay procedure |

## Positive properties retained

- signatures never imply authority by themselves;
- private keys remain outside canonical objects and the trusted verifier;
- detached signatures preserve target identity;
- grant intervals are half-open and the kernel reads no ambient clock;
- M1.1 bytes remain unchanged;
- domain-separated exact-digest signing and canonical base64url remain the foundation.

production security claim. M2.1 remains disabled by default and cannot append durable lineage.
